# wk10-srs.md — Software Requirements Specification (SRS) ฉบับสมบูรณ์

ระบบ POS ร้านกาแฟ **Baristech Cafe** (หลายสาขา) · กลุ่ม BarisTech

เอกสารนี้รวบรวมความต้องการของระบบจากงานสัปดาห์ที่ 3–4 (ความต้องการและ User Story), สัปดาห์ที่ 7 (ER Diagram) และสัปดาห์ที่ 10 (Input/Output Design) ไว้ในไฟล์เดียว เนื้อหาละเอียดอยู่ในไฟล์ต้นทางตามที่อ้างอิงไว้

---

## 1. บทนำ

### 1.1 วัตถุประสงค์
ลดความล่าช้าและข้อผิดพลาดจากการจดออเดอร์ด้วยมือในร้านกาแฟ 3–5 สาขา พร้อมจัดการสต็อกวัตถุดิบและสรุปรายงานยอดขาย (ที่มา: การสัมภาษณ์ใน `wk03-requirements.md`)

### 1.2 ขอบเขตระบบ
- **จะทำ:** รับออเดอร์หน้าร้าน, คิดเงินและเงินทอน, ออกใบเสร็จ, ลำดับคิวส่งบาริสต้า, จัดการเมนูและสต็อกวัตถุดิบ (ตัดสต็อกอัตโนมัติ), รายงานยอดขาย
- **ไม่ทำ:** ระบบบัญชีภาษีเต็มรูปแบบ

### 1.3 ผู้ใช้ระบบ
| ผู้ใช้ | หน้าที่ในระบบ |
|---|---|
| แคชเชียร์ (พนักงานหน้าร้าน) | รับออเดอร์ ชำระเงิน ดู/ยกเลิกออเดอร์ของสาขาตัวเอง |
| เจ้าของร้าน | จัดการเมนูและสต็อกวัตถุดิบ ดูรายงานยอดขายทุกสาขา |
| บาริสต้า | รับออเดอร์ที่ต้องทำ (หน้าจอฝั่งบาริสต้ายังไม่ได้พัฒนา) |

### 1.4 ข้อจำกัด (Constraints)
งบประมาณ 60,000–80,000 บาท · เสร็จภายใน 3–4 เดือน (ประมาณ 16 สัปดาห์)

## 2. ความต้องการเชิงหน้าที่ (Functional Requirements)

| รหัส | ความต้องการ | สถานะใน prototype |
|---|---|---|
| FR-01 | บันทึกออเดอร์ พร้อมเลขโต๊ะหรือประเภทการทาน | ทำแล้ว |
| FR-02 | คำนวณยอดรวม เงินทอน และแสดงยอดชำระ | ทำแล้ว |
| FR-03 | ส่งออเดอร์และแสดงลำดับคิวที่หน้าจอบาริสต้า | ส่งข้อมูลถึงบาริสต้าแล้ว (สถานะ `pending`) แต่ยังไม่มีหน้าจอบาริสต้า |
| FR-04 | จัดการวัตถุดิบ และตัดสต็อกอัตโนมัติหลังชำระเงิน | ทำแล้ว |
| FR-05 | แสดงจำนวนคงเหลือของวัตถุดิบ | ทำแล้ว (หน้าสต็อกวัตถุดิบ) |
| FR-06 | ออกใบเสร็จรับเงิน | ทำแล้ว (พิมพ์ซ้ำได้) |
| FR-07 | สรุปรายงานยอดขายรายวัน รายเดือน และแยกตามสาขา | ทำแล้ว |
| FR-08 | แสดงอันดับเมนูยอดนิยม | ทำแล้ว (ตารางยอดขายแยกตามเมนู เรียงจากมากไปน้อย) |
| FR-09 | แสดงจำนวนที่ขายได้และเตือนสต็อกตั้งแต่ตอนเลือกสินค้า (เพิ่มสัปดาห์ 13) | ทำแล้ว |
| FR-10 | แคชเชียร์ดูประวัติออเดอร์ พิมพ์ใบเสร็จซ้ำ และยกเลิกออเดอร์ที่ยังไม่เริ่มทำ (เพิ่มสัปดาห์ 13) | ทำแล้ว |
| FR-11 | สรุปยอดขายรวมต่อเมนู ตามสาขาและช่วงเวลา (เพิ่มสัปดาห์ 13) | ทำแล้ว |

## 3. ความต้องการที่ไม่ใช่เชิงหน้าที่ (Non-functional Requirements)

| รหัส | ความต้องการ |
|---|---|
| NFR-01 | คำนวณยอด ออกใบเสร็จ และอัปเดตสต็อกภายใน 2 วินาทีหลังยืนยันการชำระเงิน |
| NFR-02 | ส่งข้อมูลออเดอร์ไปบาริสต้าภายใน 2 วินาที |
| NFR-03 | หน้าจอใช้งานง่าย พนักงานเรียนรู้ขั้นพื้นฐานได้ภายใน 1–2 วัน |
| NFR-04 | กำหนดสิทธิ์การเข้าถึงข้อมูลตามบทบาท (บังคับที่ฝั่ง server) |
| NFR-05 | อัปเดตเมนู ราคา และวัตถุดิบได้โดยไม่กระทบการรับออเดอร์หน้าร้าน |
| NFR-06 | องค์ประกอบสำคัญของขั้นตอนชำระเงิน (เช่น ช่องรับเงิน) ต้องเด่นชัด ผู้ใช้ใหม่หาเจอเอง (เพิ่มสัปดาห์ 13) |

## 4. User Story และ Acceptance Criteria (สรุป)

รายละเอียด Given–When–Then อยู่ใน `wk04-user-stories.md`

| User Story | สรุป | Acceptance Criteria หลัก |
|---|---|---|
| US-01 รับออเดอร์และคำนวณราคา | พนักงานเลือกสินค้า ระบบคำนวณยอดรวมอัตโนมัติ | ต้องมีรายการสินค้า · ราคาและจำนวนต้องมากกว่า 0 · ยอดรวม = ราคา × จำนวน |
| US-02 ระบุประเภทการทาน | ทานที่ร้านหรือกลับบ้าน | ทานที่ร้านต้องระบุเลขโต๊ะ · กลับบ้านไม่ต้อง |
| US-03 ใช้ส่วนลด | หักส่วนลดจากยอดรวม | ยอดชำระ = ยอดรวม − ส่วนลด |
| US-04 ชำระเงินและเงินทอน | ตรวจจำนวนเงินที่รับ | เงินไม่พอต้องแจ้ง "จำนวนเงินไม่เพียงพอ" · เงินทอน = เงินที่รับ − ยอดชำระ |
| US-05 ตรวจสอบวัตถุดิบ | กันรับออเดอร์ที่ทำไม่ได้ | วัตถุดิบพอจึงยืนยันได้ · ไม่พอแจ้ง "วัตถุดิบไม่เพียงพอ" |
| US-06 บันทึกและดำเนินการออเดอร์ | บันทึก ส่งบาริสต้า ออกใบเสร็จ | บันทึกสถานะชำระเงิน · ส่งข้อมูลบาริสต้า · ออกใบเสร็จ |

## 5. ข้อมูลของระบบ (สรุปจาก ER Diagram)

ฐานข้อมูล MySQL 11 ตาราง: `branches`, `employees`, `categories`, `menu_items`, `ingredients`, `menu_item_ingredients` (สูตรวัตถุดิบ), `orders`, `order_items`, `stock_movements`, `receipts`, `branch_daily_counters` (เลขคิวรายวัน)

- ภาพและรายละเอียด: `wk07-er-diagram.md` และ `images/wk07-er-diagram-final.png`
- โครงสร้างตาราง: `code/schema.sql` (ฉบับสัปดาห์ 7 เดิมอยู่ที่ `wk07-schema.sql`)
- ยอดรวม ยอดสุทธิ และเงินทอนของออเดอร์ไม่เก็บในตาราง คำนวณสดจากรายการสินค้า

## 6. การออกแบบ Input/Output (สรุป)

รายละเอียดอยู่ใน `wk10-input-output-design.docx` และ `wk10-wireframe.docx`

| หน้าจอ | ผู้ใช้ | Input หลัก | Output หลัก |
|---|---|---|---|
| เข้าสู่ระบบ | ทุกคน | ชื่อผู้ใช้ รหัสผ่าน | เข้าสู่หน้าตามบทบาท |
| POS รับออเดอร์ | แคชเชียร์ | เมนู จำนวน ประเภทการทาน เลขโต๊ะ ส่วนลด วิธีชำระ เงินที่รับ | ยอดรวม ยอดสุทธิ เงินทอน ใบเสร็จและเลขคิว |
| ประวัติออเดอร์ | แคชเชียร์ | กดดูใบเสร็จ / ยกเลิก | รายการออเดอร์วันนี้ ใบเสร็จ |
| จัดการเมนู | เจ้าของ | ชื่อ หมวดหมู่ ราคา สูตรวัตถุดิบ รูป | รายการเมนูของสาขา |
| สต็อกวัตถุดิบ | เจ้าของ | ชื่อ หน่วย เกณฑ์เตือน จำนวนที่เติม | จำนวนคงเหลือ สถานะใกล้หมด |
| แดชบอร์ดยอดขาย | เจ้าของ | สาขา ช่วงวันที่ | ยอดขายรวม จำนวนออเดอร์ สรุปรายวัน/เดือน/วิธีชำระ/สาขา/เมนู |
